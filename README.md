# Агрегатор уникальных новостей для Telegram

Сервис читает несколько Telegram-каналов, отбрасывает повторяющиеся сюжеты и публикует в ваш канал только те новости, которых ещё не было.

## Какие технологии используются

| Слой | Стек | Зачем |
| --- | --- | --- |
| Сбор постов | Публичные страницы `t.me/s/<channel>` + `httpx` + `BeautifulSoup` | Бот Telegram не умеет читать чужие каналы. Публичный превью даёт доступ без user-session. |
| Опциональный realtime | Telethon / MTProto user-session | Если позже понадобится мгновенная лента и закрытые каналы, куда вы уже подписаны. |
| Дедупликация | нормализация текста, SHA-256, RapidFuzz `token_set_ratio`, Jaccard и cosine | Ловит копипаст и слегка переписанные новости. |
| Публикация | Telegram Bot API (`sendMessage` / `sendPhoto`) | Бот, которого вы добавляете админом в свой канал. |
| Хранение | SQLite + SQLAlchemy | Хеши, источники, статусы `published` / `duplicate` / `skipped`. |
| API | Python 3.12, FastAPI, Pydantic | Управление источниками, настройками и ручной сбор. |
| Админка | Vue 3, Vite, Pinia, TypeScript, Tailwind | Добавление каналов, порог похожести, просмотр ленты. |

Почему не один только Bot API: обычный бот не получает посты из каналов, где он не админ. Поэтому чтение и публикация разделены: **сборщик** ходит в публичные превью, **бот** пишет только в ваш канал.

## Как это работает

```
каналы-источники → нормализация текста → поиск похожих постов
        ↓                                      ↓
   новый сюжет                          повтор / слишком короткий
        ↓
  публикация ботом в ваш канал
```

1. Сборщик забирает последние посты из указанных публичных каналов.
2. Текст чистится: ссылки, упоминания, хештеги, «подписывайтесь», HTML.
3. Если хеш уже встречался — это точный дубль.
4. Если похожесть выше порога (по умолчанию 82%) — это пересказ той же новости.
5. Короткий служебный пост отбрасывается.
6. Уникальная новость уходит в ваш канал с подписью источника.

Демо-режим работает без Telegram: в комплекте есть три вымышленных канала с намеренными повторами.

## Быстрый старт

```bash
cp .env.example .env

python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt

cd frontend && npm install && cd ..

# терминал 1
cd backend && APP_MODE=demo uvicorn app.main:app --reload --port 8000

# терминал 2
cd frontend && npm run dev
```

Откройте [http://localhost:5173](http://localhost:5173), нажмите «Собрать сейчас» или «Пересобрать демо».

## Боевой режим

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Создайте свой канал и добавьте бота администратором с правом писать сообщения.
3. В `.env` укажите:

```env
APP_MODE=live
BOT_TOKEN=123456:token
TARGET_CHANNEL=@your_channel
SOURCE_CHANNELS=channel_one,channel_two
SIMILARITY_THRESHOLD=0.82
```

4. Источники должны быть **публичными** — у них есть страница `https://t.me/s/username`.
5. Перезапустите API. Можно добавить каналы и из админки.

Публикуйте только контент, на который у вас есть право. Сервис ставит ссылку на источник и не обходит закрытые чаты.

## Что умеет дедуп

- один и тот же текст из разных каналов;
- тот же сюжет с другой шапкой, ссылкой или «читайте также»;
- близкий пересказ («ЦБ сохранил ставку 16%» и «Банк России оставил ставку 16 процентов»).

Слабое место первой версии — сильно разные формулировки одной новости. Для этого позже можно подключить эмбеддинги (`sentence-transformers` / multilingual-e5). Сейчас код дедупа вынесен в `backend/app/dedup/`, туда это добавляется без переписывания пайплайна.

## Docker

Локально:

```bash
docker compose up --build
```

API: `http://localhost:8000/api/health`  
Админка: `http://localhost:5173`

На VPS (боевой режим):

```bash
cp .env.example .env   # заполните BOT_TOKEN и TARGET_CHANNEL
docker compose -f docker-compose.prod.yml up -d --build
```

Админка слушает порт 80, API — 8000. Бот должен быть администратором канала назначения с правом писать сообщения. Источники добавляются в админке.
